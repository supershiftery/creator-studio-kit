## Project layout
- `raw/camera.mp4` — 3840x1920 (or 3840x1080), two camera angles side by side (left=front A, right=B which switches between side cam / product cam / screen recording).
- **OR `raw/edit.xml`** — a Gling xmeml/fcpxml edit list (preferred): parsed by scripts/xml_cuts.py into the ORIGINAL media path (has ALL audio tracks → real DJI swap) + kept ranges. Cuts come from the XML, not silence detection; only "next section" markers are cut on top. audio_mix builds raw/camera.mp4 from the original (copy2, NEVER hardlink) — the original is never modified. Drop the .xml in `{{PROJECTS_ROOT}}`; the watcher's new_xml_project handles it end-to-end. Optional `raw/source.mp4`: use that file as the source instead of the media path named in the XML (for a recovered/replaced original). Note Gling cloud RE-DOWNLOADS also keep only one audio track — a multi-track original must come from the recorder/camera/DJI itself, not from Gling.
- `raw/screen.mp4` — optional screen recording. `raw/music.txt` — optional 4 type beats (intro/review/showcase/outro). `raw/extra_cuts.json` — his manual removals as SOURCE-time ranges `[[a,b],...]`, subtracted at the cuts step every run (fresh-proof; the only sanctioned way to remove a flagged section). `raw/extra_keeps.json` — the opposite, source ranges put BACK before extra_cuts (e.g. a silent screen scroll the trimmer cut as dead air: cutting mid-scroll jumps the page, prada cups 3:29 "weird clip and cut"). `raw/config.json` — per-project overrides of any config.json setting. `work/timeline.json` = the kept ranges as rendered (after word_guard); the Studio maps his draft times through it, minus the intro length when he watched the intro version.
- Output: `output/final.mp4` (1920x1080, 30fps, H.264, AAC 192k), `preview_540p.mp4`, `report.md`.

## The edit (what he likes)
- Two-mic swap (scripts/audio_mix.py, "audio_mix" in config) — FULLY AUTOMATIC, his rule: ONE mic per section, never jumping mid-try-on. `identify_tracks` picks the mics by measurement (condenser = loudest in the desk window, DJI = loudest where the condenser is quiet) — never track order. The DJI block runs from the first away segment ≥8 s (condenser drops >14 dB under its own desk level for ≥1.5 s; detection lags the visual step-away ~7 s, so edges snap to Gling cuts with the wide block_snap_seconds 10 window) to the CUT where the computer segment starts (the kept clip containing the first screen run ≥2 s — that clip's opening is already desk talk, so it belongs to the condenser). Everything is clipped to kept footage so no sub-second blips land at cut edges. **DJI is gain-matched to the condenser (P85 speech-percentile of 0.5 s window levels inside vs outside the block, cap ±15 dB).** Gling mp4 exports keep only ONE track: then the low parts are boosted instead (cap +12 dB, mode "boost"); the XML flow gets the real tracks and does a true swap. Face circle is hidden during the same block. XML mode is two-phase: `ensure_source` copies the original in BEFORE transcribe/analyze (copy2, never hardlink), `apply_block_mix` runs AFTER analysis so it can use the screen runs. No Camera-A full-frame cutaways inside the block (face_full is subtracted): the Go 3S is the try-on/unboxing camera, and the desk cam has the white Go 3S sitting in frame. Non-XML original kept as raw/camera_original.mp4.
- Transcribe once (Whisper small.en, word timestamps), cache and reuse.
- Sections from spoken "next section" markers (3 markers → intro / product review / showcase / outro); cut the marker phrase ±0.5 s. Without markers (fallback): the intro is the first talking side-angle block (side runs with < 8 s gaps, ≥ 10 s), review starts where the product camera takes over after it — pre-roll before the take doesn't count (prada cups: a product shot at 0:04 of pre-roll made "hey guys" a review section, so it got the circle + turntable B-roll; "I'm talking to the audience here"). - **Never cut mid-word** (dhgate asics 2026-10-22: "dive right in[to it]" and "right now [so]" sounded clipped): `word_guard()` runs after every cut source (trimmer, Gling, take review, extra_cuts) right before the Timeline. Pitfalls:
- Restart the watcher (kill pythonw, re-run install_watcher.ps1) after editing watcher.py — the running process holds the old code. `_single_instance` makes a second launch exit silently, so a stale process must be killed first.
- On this MSYS shell, pass native Windows tools `C:/...` paths (bare `/c/...` fails with 'No such file'), and use PowerShell `Stop-Process -Id <pid> -Force` to kill PIDs — `taskkill //PID` gets its flags mangled by MSYS.
- NEVER build audio via atrim+concat segmentation: AAC frame-edge rounding makes it drift ~17 ms per cut (≈0.7 s by 2 min). audio_mix uses volume-envelope expressions instead. Verify a mix by correlating the output against each source track at several timestamps — should be ≈1.0 vs exactly one track everywhere.
- NEVER hardlink the original media into a project (ensure_source uses copy2): shutil.move/copy onto a hardlink path writes THROUGH the link and destroys the user's original file (this happened 2026-10-18 and cost the alo original its extra audio tracks). Always unlink the destination before moving a mix into place.
- Verifying a mix against the source file is meaningless if the project file is a hardlink/copy of that same file — correlation is trivially 1.0. Verify against an independent copy, or ffprobe the stream counts first.
- Away-from-mic detection assumes track 1 is a RAW main mic. On an already-mixed source (e.g. a rebuilt/recovered file whose try-on is already DJI), detection misfires (block starts late) — set the block manually from a previously validated run instead of trusting detection.
- DJI gain matching: use a speech PERCENTILE of window levels (dji_gain_percentile 85), never a median (room tone drags it) and never whole-track LUFS.
- Identify mics by MEASUREMENT, never by track position or label: per-region P85 window levels identify each track (condenser = loud at desk, silent/far in try-on; DJI = quiet at desk, loud in try-on; OBS originals may carry extra empty tracks at -160 dB). Track ORDER differs between an OBS .mkv and its remuxed .mp4 — trusting position over measurement once swapped in the Go 3S camera mic and shipped 'far away' audio (identify_tracks in audio_mix.py does this automatically). DJI block end = the CUT where the computer segment starts (the kept clip containing the first screen run ≥2 s), NOT the screen frame itself: he's already at the desk talking when that clip opens, so it belongs to the condenser. The .mkv often carries MORE audio tracks than the .mp4 remux — edit_review auto-prefers it; check before declaring tracks lost. apply_block_mix automates the whole chain (identify → away → block → gain → swap); manual mixes only for damaged sources.
- Manual cut requests (\"cut 3:01-3:26\"): map output→source time via work/cuts.json, write them to `raw/extra_cuts.json` (idempotent, survives --fresh), NEVER hand-edit work/cuts.json — a --fresh run regenerates it from the XML and silently resurrects the removed clips.
- After rebuilding a damaged/rebuilt source, verify the try-on is the DJI track (correlate vs an independent DJI copy) AND that speech levels match (P85 of window dB within ~3 dB of desk speech) BEFORE uploading. He costs money on every bad upload.
- Replacing a same-named file on Drive repeatedly does NOT reliably update what he watches (Drive keeps versions; the player and Drive-for-Desktop cache serve stale copies). After 1-2 replacements of the same name, deliver under a fresh name ("<project> FINAL.mp4") so he can't watch a stale version.
- Before claiming an audio fix, verify the exact bytes being uploaded: hash the Drive copy and the local final and compare; and always check audio in the source-time mix file (raw/camera.mp4), never final.mp4 — the music bed destroys correlation.
- Speech correlation needs <5 ms alignment: AAC encoder priming differs per file (≈44 ms), so a raw Pearson corr can read ~0.2 against the CORRECT track — always cross-correlate with a lag sweep (±120 ms, 0.25 ms steps) before concluding the wrong track is playing.
- Before declaring a multi-track original lost, look for the recorder's own sibling file (OBS writes .mkv next to the remuxed .mp4) — the MKV kept all tracks after the MP4 was destroyed. Gling cloud re-downloads keep only one track (captured in Project layout above).
- Channel detection reads the transcript from just before the first kept cut (XML originals include pre-roll and false takes); aliases are checked before filler truncation, and the LAST intro take wins.
- Moving/renaming large media files can throw PermissionError even when nothing is obviously holding them (Drive sync, indexer, a just-finished ffprobe) — wrap moves in a retry loop with backoff (see `_move` in scripts/audio_mix.py) rather than assuming the file is stuck.
- A crashed pre-processing step can leave a half-moved state (backup copied, original still in place) that looks 'already done' to the cache check — when a step is marked complete but its outputs are missing, compare all three files (original/backup/result) and finish the move manually before re-running. The same applies to re-mixing an already-mixed file: boost/swap compounds (double gain on try-on), so the mix is idempotent via its markers (camera_original.mp4, or audio_mix.json in XML mode) — never rebuild a mix unless those are deliberately cleared.

- To remove a section he flags (a retake Gling kept, a clip he wants gone): map his output times to source, append the source range to raw/extra_cuts.json (applied by edit_review.subtract() at the cuts step), and re-render — no re-transcribe or re-analysis needed. Hand-editing work/cuts.json directly is forbidden — see the extra_cuts.json rule above. To rebuild the mix differently, ALSO delete work/audio_mix.json and work/levels.json (levels.json caches the voice loudness of the old mix — a stale one mis-sets the music duck and the +4 dB cap).
